THINK TO DEPLOY: HR Analytics & RAG Chatbot

Multilingual training analytics and a RAG-based HR chatbot, built for Safran.

PythonRAGSentence TransformersFastAPIStreamlitDocker

Overview

A two-part AI solution built for Safran's HR function: a training-analytics module that mines multilingual evaluation feedback, and a retrieval-augmented-generation (RAG) chatbot that answers employee HR questions from internal documentation.

Problem

Safran faced two interconnected HR challenges: extracting actionable insight from training evaluation feedback written in French, Arabic, and English, and giving employees fast, accurate access to HR information without exposing sensitive data or depending on an external API.

Approach

  1. Ingest multilingual feedbackCollect training evaluation comments and satisfaction scores across French, Arabic, and English.
  2. Run sentiment analysis per languageScore sentiment per language, then surface correlations between satisfaction criteria and thematic patterns in the open-text comments.
  3. Build a RAG knowledge baseEmbed HR policy documents with sentence-transformers so the chatbot retrieves the relevant passage before answering, instead of relying on the LLM's untethered knowledge.
  4. Serve profile-aware answersCondition each answer on both the retrieved context and the employee's profile, so two employees asking the same question can get correctly different answers.
  5. Containerize each service independentlyPackage the analytics dashboard and the chatbot as separate Docker containers (FastAPI backend, Streamlit frontend), running an open-source LLM locally rather than calling an external API, with dependencies managed per-service via uv.

Results

Delivered as a proof of concept rather than a benchmarked model, so no accuracy table is reported. What shipped:

ComponentOutcome
Training analyticsMultilingual (FR/AR/EN) sentiment dashboard with satisfaction-criteria correlations and thematic extraction
HR chatbotRAG-based, profile-aware answers grounded in internal policy documents
DeploymentIndependent Docker containers per service, local open-source LLM inference, no external API dependency
