Custom Support Chatbot: LangGraph Agent

An agentic customer-support assistant with a human-in-the-loop safety layer.

LangGraphLangChainMulti-LLMHuman-in-the-LoopSQLite

Overview

A LangGraph-based customer-support agent, built around a travel-booking use case, that can look up and modify bookings but pauses for human approval before taking any sensitive action.

Problem

Giving an LLM agent direct write access to real systems (bookings, cancellations, payments) is risky without a way for a human to review and approve its intended actions before they execute.

Approach

  1. Model the agent as a graphA LangGraph state machine with an assistant node looping against a tools node: the assistant decides whether to answer directly or call a tool, and tool results feed back into the assistant's next turn.
  2. Add an interrupt-and-approve checkpointBefore any sensitive tool call executes, the graph pauses and surfaces the proposed action; the user can approve it, or redirect the agent with new instructions passed back in as a tool message.
  3. Split tools into modular domainsFive tool modules, flights, hotels, car rental, excursions, and policy lookup, each querying a shared local database rather than one monolithic tool file.
  4. Make the LLM backend swappableRoute model calls through a config layer supporting OpenAI, Anthropic, Google Gemini, Mistral, and local Ollama models, so the same agent graph runs identically regardless of provider.
  5. Add live web search as a fallback toolWire in Tavily and DuckDuckGo search for questions the internal tools and database can't answer.

Results

Human-in-the-loop flow: user asks the agent to change a booking → agent proposes the specific tool call → graph interrupts and shows the user exactly what will run → user types y to approve, or gives new instructions to redirect the agent → only then does the tool call execute.
